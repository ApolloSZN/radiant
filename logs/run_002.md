# Run 002 — quantitative maintenance closure

## Objective
Remove the central scientific overclaim in v0.2: non-empty maxRAF is not sufficient for material self-maintenance. Implement a quantitative second gate.

## Starting state
v0.2 unpacked and independently verified: 17/17 tests passed.

## Work completed
- Added `radiant/engines/viability.py`.
- Added a generic linear-program flow model with process input/output coefficients, finite process capacity, explicit import limits, maintenance/replacement demand, and energy budget.
- Added `quantitative_closure()`: maxRAF is gate 1; LP feasibility over only the RAF core is gate 2. The two verdicts are never conflated.
- Added migration `003_quantitative_viability.sql` for flow processes, coefficients, maintenance requirements, import limits and auditable viability runs.
- Added four falsification-oriented tests.
- Renamed the semantic meaning of `inception_time` to `topological_closure_time`; retained alias only for compatibility and explicitly documented that this is not a life criterion.

## Commands/tests
`pytest -q` -> **21 passed in 0.42 s** (17 prior + 4 new).

## Quantitative falsification cases
1. A network has a valid RAF but tool-production capacity 0.4 against maintenance demand 1.0: topological closure PASS, material viability FAIL.
2. Raising tool capacity to 2 with energy requirement 2/unit and budget 3: material viability PASS at tool flux 1.
3. Lowering energy budget to 1.9: viability FAIL despite adequate production capacity.
4. External tool import can satisfy maintenance, but the import appears explicitly in the solution rather than being mistaken for internal closure.

## Architectural decision
The core state is now a temporal attributed dependency graph **plus** a quantitative stock/flow feasibility model **plus** an evidence ledger. RAF is structural closure only. A claim of material self-maintenance requires quantitative feasibility under explicit resource, capacity, energy and replacement assumptions.

## Failures / limitations
- LP is steady-state, not yet dynamic stock depletion/recovery.
- It treats coefficients as deterministic; uncertainty distributions are not propagated through LP yet.
- It does not yet model catalyst/tool minimum stock required to enable a process separately from replacement flow.
- No real measurements are loaded; all current examples remain illustrative.
- No live Postgres execution performed.

## Direction check
Materially improved physical/resource validity and falsifiability. It prevents the exact false positive identified in v0.2 (RAF exists but replacement rate is insufficient).
