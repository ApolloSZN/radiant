# Run 015 — v0.14-rc3

## Objective
Correct the final hosted-CI release semantics rather than treating an in-progress workflow as proof of a green workflow.

## Starting state
v0.14-rc2 had 60 passing tests and a commit-bound GitHub Actions environment attestation. That was stronger than a local proxy, but the gate name `hosted_ci_green` still overclaimed: the attestation is generated before the workflow completes.

## Build/test cycles
1. Added `radiant.hosted_release` with validation for a post-run record requiring `status=completed`, `conclusion=success`, a GitHub Actions run URL, numeric run ID, repository, and 40-hex commit binding.
2. Added adversarial tests showing in-progress, failed, or wrong-commit runs cannot satisfy the final gate.
3. First integration exposed a real design failure: requiring post-run evidence inside the same CI job makes the job impossible to complete. Rejected that formulation.
4. Split release verification into `ci` and `final` modes. CI mode requires hosted execution but explicitly does not claim completed success. Final mode requires both execution evidence and the completed-success record.
5. Updated GitHub Actions to run `python -m radiant.release --run --ci`.
6. Added ADR 004 documenting the two-phase rule and a two-minute interview walkthrough.

## Results
- 63/63 tests pass locally.
- Existing evaluation harness remains green.
- Final local release state: 9/11 gates. The two missing gates are exactly the two facts a local environment cannot establish: execution of this commit on hosted CI and successful completion of that hosted run.
- No scientific metric was changed or relabeled. Strict-vintage BLS remains a negative result (-31.6% relative to baseline); retrospective sequencing and battery results remain retrospective.

## Adversarial direction check
This run materially improved reproducibility and falsifiability. It removed a circular release claim: a running CI job cannot certify its own eventual success. The weakest link is now external publication/hosted execution, not local machinery.

## Exact next action
Push rc3 to the intended Radiant repository; let hosted Actions pass CI mode; after completion, capture GitHub's completed/success state bound to the same SHA; run final verification; only 11/11 permits v1.0.
