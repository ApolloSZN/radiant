## Work performed
1. Inspected `radiant/engines/viability.py` and its tests.
2. Found a real model bug: steady-flow constraints were generated only for `maintenance` keys. A process could therefore consume an unmaintained raw resource without any production or explicit external supply. This contradicted the module's own stated physical semantics.
3. Rewrote balance construction so every item in process inputs/outputs, maintenance, or external supply receives a material-balance inequality.
4. Added `balance_slack` to viability results for auditability across all resources, not only maintained stocks.
5. Added finite-horizon constant-rate stock-flow viability with initial stocks, maintenance rates, bounded external inflows, process capacities, integrated energy, and terminal non-depletion.
6. First finite-horizon implementation failed on a legitimate zero-variable LP because SciPy rejects empty objective vectors. Rejected that implementation path and added an explicit analytic feasibility branch for inherited-stock-only systems.
7. Re-ran tests and complete reproduction.

## New falsification evidence
- Unproduced ore consumed by a tool-making process is now infeasible rather than free.
- 2 ore/tool with ore inflow cap 1.9 cannot maintain 1 tool/time; cap 2.0 can.
- Inherited stock 10, depreciation 1/time, horizon 5: survival is feasible if depletion is allowed, but self-maintenance is infeasible if terminal stock must return to initial level.
- A replacement process at rate 1/time with sufficient ore and energy restores non-depleting viability.
