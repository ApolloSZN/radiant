# Run 003 — first real evidence + backtest/scoring vertical slice

## Objective
Move the binding constraint from ontology to evidence: ingest a real public technological progress series and force the historical-evaluation machinery to distinguish a useful retrospective test from a genuinely no-leak historical replay.

## Work completed
- Verified inherited repository: 21/21 tests passed before changes.
- Added 47 observations from the NHGRI DNA sequencing cost series (Sep 2001–Apr 2014), with cost/Mb and cost/genome, source tier and provenance URL.
- Added `radiant/data/backtest.py`: CSV ingestion, bitemporal visibility filter, log-linear curve fitting, rolling one-step forecasts, threshold crossings, probabilistic threshold forecasts, Brier score and log score.
- Added 5 tests covering ingestion/provenance, future-recording exclusion, regime-shift behavior, known threshold crossings, and finite probabilistic scoring.
- Added migration 004 separating `source_available_at` from `recorded_at`, plus an explicit backtest mode enum. This prevents retrospective data from masquerading as a no-leak historical replay.
- Corrected README language: non-empty RAF is a topological closure event, not an inception-of-life criterion.

## Critical failure / negative result
This dataset **does not yet pass Gate 1**. The current transcription was recorded after the historical observations. Therefore a strict bitemporal replay at (say) 2010 correctly sees zero rows. Using observation dates alone is a retrospective rolling-origin test, not proof of what the map could have known then. This distinction is now enforced in schema and tests rather than hidden.

The 2008 next-generation sequencing regime change is also a direct falsification of a single stationary progress curve: error rises ~7x versus the pre-2008 segment. Short rolling windows recover faster than all-history fitting. Surprise/regime-break handling is therefore not optional.

## Direction check
Material improvement: empirical grounding, falsifiability, predictive scoring, and anti-leakage discipline. The system produced a useful negative result: its first real series exposes both a regime-change failure and a provenance-vintage failure.

## Current weakest link
Historical source vintages. We need independently dated source snapshots or contemporaneous primary-source releases before claiming Gate 1. After that, storage and compute should be ingested under the same contract.

## Exact next executable action
Build a historical-vintage evidence table from contemporaneous NHGRI releases/archived source snapshots, attach availability evidence and hashes, then rerun the sequencing forecasts in `historical_vintage` mode. In parallel, add automated surprise/regime-break detection and test whether it reduces post-break forecast loss without lookahead.
