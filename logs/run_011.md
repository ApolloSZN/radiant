# Run 011 — Radiant v0.12

Objective: make the v1.0 release criteria executable rather than aspirational, while advancing the transformer effect-identification path without inventing effects.

Starting state: v0.11, 50 passing tests. The scientific engine had real retrospective data and transformer accounting, but no CI-gated headline eval, no clean-machine reproduction template, and no predeclared causal panel falsification contract.

Work completed: added `radiant.eval`, which compares the system against explicit baselines and writes a machine-readable artifact. Sequencing MALE is 0.1762 versus 0.7836 all-history (77.5% lower). Battery MALE is 0.1461 versus a rolling-5 baseline of 0.1648 (11.4% lower). Both results are tagged retrospective real data and cannot masquerade as strict historical-vintage evidence. Added GitHub Actions, dependency file, Dockerfile and one-command reproduction script. Added ADRs covering evidence classes, RAF/material viability separation, and prequential model selection.

Transformer work: logged primary evidence for Prolec Goldsboro (+200 medium-power units/year projected by 2030), Hitachi South Boston groundbreaking on 2026-06-29 (no units/year disclosed), and Hitachi Mississippi announcement on 2026-09-15 (relative doubling, no absolute unit rate). Added an event-study primitive that refuses causal identification if pre-trends or placebo checks fail; tests cover clean recovery and both rejection paths.

Verification: 54/54 pytest tests pass locally; `python -m radiant.eval` passes; demo runs. Hosted CI and Docker execution are not claimed verified in this environment.

Negative results / guardrails: retrospective eval != no-leak historical replay; medium-power capacity != LPT capacity; investment/jobs/relative doubling != absolute LPT unit rate. No transformer intervention effect is identified yet.

Adversarial direction check: this run materially improved reproducibility, falsifiability, and release discipline. The scientific weakest link remains strict historical-vintage and causal effect evidence. The shipping weakest link is end-to-end release verification/documentation.

Exact next action: construct strict-vintage evaluation from independently dated primary releases, and implement a release verifier that fails closed if any v1.0 ship-bar item is missing or uses the wrong evidence class.
