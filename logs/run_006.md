# Radiant Run 006 — v0.7

## Objective
Continue past retrospective curve-fitting by adding a third empirical domain, make forecasts immutable/scorable as first-class artifacts, and close the recursive traceability gap in counterfactual knockouts.

## Starting state
v0.6 independently verified at 32/32 passing tests. Sequencing and battery series were real but retrospective; sequencing-specific adaptation had already failed to generalize to battery prices. Historical-vintage Gate 1 remained open.

## Work completed
1. Added `data/compute/leading_ai_gpu_price_performance.csv`: P100, V100, A100 and H100 price-performance observations from Epoch AI's hardware price-performance analysis. Source tier is T1 and every row is explicitly retrospective with recorded date 2024-10-23.
2. Added `load_compute_series()` and a hard test that a 2022 replay sees zero of those rows. This prevents a later retrospective hardware dataset from masquerading as contemporaneous knowledge.
3. Added `radiant/data/forecast_ledger.py`. Forecast registration binds cutoff, target date, prediction, model specification and sorted evidence IDs into a deterministic SHA-256 artifact hash. Resolution is separate and scores binary forecasts with Brier/log loss and positive continuous forecasts with log/factor error.
4. Added migration 005 for immutable forecast registration and one-time resolution records.
5. Added `recursive_knockout_trace()`. It emits an explicit causal DAG linking intervention roots -> unavailable items -> failed producer processes -> downstream unavailable items/processes. On the illustrative ore-cut network it explains 10 dropped processes with 18 nodes and 22 directed causal edges.
6. Added five tests: compute-vintage anti-leakage, recursive trace structure, forecast hash reproducibility/evidence-order invariance, resolution scoring, and invalid-forecast rejection.

## Quantitative outputs
- Tests: 37 passed, 0 failed (32 inherited + 5 new).
- Epoch four-chip slice: simple log-linear fit implies ~1.51x/year price-performance improvement (~1.67-year doubling). This estimate is NOT promoted as a general trend because n=4 and the observations mix precision conventions; Epoch's broader published analysis is the authoritative trend estimate.
- Recursive toy ore knockout: 10 processes dropped; trace graph has 18 nodes / 22 edges.

## Evidence/provenance
Compute source: Epoch AI, "Performance per dollar improves around 30% each year" (published 2024-10-23; downloadable hardware dataset subsequently updated). Reported comparison values: P100 ~1.3e9, V100 ~6.7e9, A100 ~1.3e10, H100 ~2.2e10 FLOP/s per inflation-adjusted dollar. Epoch's broader GPU work uses hundreds of GPUs and reports materially slower long-run doubling than the four-point leading-chip slice, so the four-point fit is retained only as a pipeline fixture, not evidence of a universal law.

## Negative results / honesty boundary
- Third-domain data still does not solve historical-vintage replay: it is retrospective.
- Four leading chips are too sparse and heterogeneous in precision to evaluate the cross-domain selector fairly. No selector performance claim is made from this dataset.
- Recursive trace is structurally exact for the RAF graph but does not yet propagate quantitative LP shadow prices, inventory depletion, substitution, or uncertainty.
- Forecast ledger is code + schema; no prospective forecast has yet matured to resolution.

## Direction check
Material improvement in reproducibility, traceability, falsifiability, and empirical breadth. The project now has an auditable forecast object that cannot be silently rewritten after outcomes arrive, and counterfactual traces preserve intermediate causal chains rather than only root labels.

## Binding constraint
Historical information vintage remains the primary blocker to Gate 1. The next major empirical blocker is a real production network with quantities/capacities, because toy RAF/LP networks cannot establish consequential constraint-resolution ability.

## Exact next executable action
Build the first real production-network vertical slice, preferably large-power transformers: acquire public BOM/material/input-output/lead-time/capacity evidence, encode it with uncertainty and provenance, connect quantitative viability/knockout tracing, and identify which claimed bottlenecks survive sensitivity analysis. In parallel, continue collecting contemporaneous historical vintages sufficient for at least one strict no-leak forecast replay.
